<pasted_content id="259f">
I opened PR #70, “displayd: server tests + docs” (#70). I made no runtime changes.

The Sidecar server is the /surfaces API in daemon_http_surfaces.py. It runs inside the daemon, so there is no separate process.

New tests are in tests/test_surfaces_server.py (15 tests). The existing test_surfaces_http.py covered happy paths and auth on four routes, so these fill the gaps:

Auth: the bearer token is enforced on every POST sub-route (update, heartbeat, content, targeted content, touch, columns, column action) plus GET and DELETE. Wrong, missing and non-Bearer headers all get 401. A refused request changes nothing. The API stays open when no token is configured.
Bad requests: malformed, empty and non-object bodies return 400. Non-numeric since or wait returns 400. Unknown sub-routes return 404, as does an unknown surface on each sub-resource. An unsupported touch returns 409 and records no event. An unknown column returns 404.
Idle clock: reads and heartbeats don’t count as operator activity, mutating sends do, and 401s don’t.

I also added a short “Sidecar server” section to the README with how to run it, auth, example calls and the error codes.

Test results: the three surface suites pass (73 tests). The full suite takes about 8 minutes and has 4 failures and 2 errors on main too: the litehtml engine isn’t built here, plus beads/panel rendering and switch-latency fixtures. My full run showed one extra failure, a timing-budget test (retro_grid at 528 ms against a 500 ms limit). I didn’t investigate it further, but my changes only add a test file and README text.

One current behaviour your tests might trip over: a send that fails validation (for example a 415 for an unsupported content type) still counts as operator activity, because the handler records activity before delivery. I left it as is, since you asked for no behavior changes, and didn’t assert on it.
